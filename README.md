# تطبيق الشيخة — الإدارة والعملاء

مشروع Flutter عربي (RTL) يتكون من تطبيقين Android مستقلين يتشاركان مشروع Firebase واحداً:

- `admin_app/`: تطبيق الإدارة.
- `client_app/`: تطبيق العملاء.
- `shared/`: تكامل التخزين المحلي المشترك على الجهاز نفسه.
- `firestore.rules`: قواعد حماية بيانات Firestore.
- `.github/workflows/android-build.yml`: بناء APK للتطبيقين ورفعهما كملفات Actions Artifacts.

## المزايا الموجودة

### تطبيق الإدارة
- تسجيل دخول خاص بحسابات تحمل الدور `admin`.
- إدارة الكادر: البيانات، الأسعار بالدينار العراقي، التوفر، العنوان العراقي، والصور (حتى 10).
- إدارة أرشيف الجلسات والصور.
- إدارة البانرات والإعلانات.
- عرض الحجوزات وتأكيدها أو رفضها.
- محادثات العملاء، الردود، مشاركة ملفات الكادر، وإنشاء بطاقة حجز من المحادثة.

### تطبيق العملاء
- إنشاء حساب عميل وتسجيل الدخول باسم مستخدم وكلمة مرور.
- استعراض الكادر والبحث وعرض الملفات والصور.
- المفضلة.
- إرسال طلبات الحجز ومتابعة حالتها.
- أرشيف الجلسات والبانرات والإعلانات.
- محادثة الإدارة ومشاركة ملف عضو الكادر.
- تعديل بيانات الحساب وكلمة المرور.

## البنية المجانية

- Firebase Authentication لتسجيل الحسابات.
- Cloud Firestore للبيانات والمزامنة بين الأجهزة.
- Get Pronto Free لاستضافة صور الكادر والجلسات والبانرات.
- لا يعتمد إعداد Firebase الحالي على Cloud Functions أو Firebase Storage؛ لذلك لا يحتاج نشر التطبيق إلى تفعيل خطة Blaze.
- التخزين المحلي المشترك بين التطبيقين يعمل عند تثبيتهما على الجهاز نفسه، بينما Firestore هو مصدر البيانات المتزامن عبر الإنترنت.

### الصور

يرفع تطبيق الإدارة الصور إلى Get Pronto باستخدام Public Key المخصص للرفع فقط. تحفظ روابط HTTPS في Firestore. يدعم التطبيقان الروابط الجديدة ويستمران في عرض الصور القديمة المخزنة بصيغة Base64.

لا تضع أي Get Pronto Secret Key في التطبيق أو المستودع. مفتاح Public Key محدود بالرفع فقط ومخصص للاستخدام من جهة العميل.

## إعداد Firebase لأول مرة

1. افتح مشروع Firebase `alshaikha`.
2. فعّل Email/Password في Authentication.
3. أنشئ قاعدة Firestore في وضع الإنتاج.
4. انشر قواعد الحماية الموجودة في `firestore.rules` باستخدام:
   `firebase deploy --only firestore:rules`
5. لإنشاء أول مدير دون Cloud Functions:
   - من Authentication أضف مستخدماً ببريد `username@alshaikha.app` وكلمة مرور.
   - انسخ UID الخاص بالمستخدم.
   - في Firestore أنشئ مجموعة `profiles` ومستنداً يكون معرّفه UID نفسه.
   - أضف الحقول: `uid` (String)، `username` (String)، `displayName` (String)، `role` (String وقيمته `admin`).
   - بعد حفظ المستند، سجّل الدخول في تطبيق الإدارة باسم المستخدم وكلمة المرور.
6. ينشئ العميل حسابه بنفسه من تطبيق العملاء. لا تمنح دور `admin` لأي حساب عميل.

إنشاء حسابات الإدارة يتم من Firebase Console فقط، لأن إنشاء مستخدم Auth بصلاحيات إدارية من تطبيق الهاتف يحتاج خادماً موثوقاً، وهذا المشروع يتجنب خدمات الخادم المدفوعة.

## البناء

يعمل GitHub Actions عند فتح Pull Request إلى `main)، أو الدفع إلى `main)، أو التشغيل اليدوي. ينتج ملفين:

- `admin_app-apk`
- `client_app-apk`

بعد نجاح Workflow، افتح صفحة Actions ثم تشغيل البناء ونزّل ملف APK المناسب من Artifacts. لا تعتبر النسخة جاهزة للتوزيع قبل تثبيتها واختبار تسجيل الدخول والرفع والمزامنة على جهاز Android.

## ملاحظات تشغيلية

- لا تضع بيانات شخصية حقيقية قبل اختبار قواعد Firestore.
- خدمة الصور المجانية لها حصص استخدام وحدود لحجم الملف؛ راقب الاستهلاك من لوحة Get Pronto.
- إشعارات التطبيق الحالية داخل التطبيق وتُحدّث بالمزامنة الدورية؛ لم تتم إضافة إشعارات Android Push.
